## 0. 一句话结论

这条策略的真正阻塞点不是模型、不是预注册、不是样本量，而是两条：

1. **算术上**：结构对的成本恒等于 `1 + 市场隐含分裂概率 + 执行开销`。
   v0.8 预注册选定的执行方式（一腿挂单 + 另一腿 FOK 吃单）会让半价差
   相互抵消，成本 **恒 > 1**。它要求的 `all_in ≤ 0.99` 在一个自洽的市场里
   永远不可能满足。唯一能算出正 floor 的形态是**两腿都挂单**，而 v0.8 明确
   没有做这个。
2. **工程上**：仓库根本没有能下单的通道。`py-clob-client 0.34.6` 是已归档的
   V1 SDK，`compatibility.py` 里 8 项实盘检查**全部为 false**，
   `assert_new_orders_disabled()` 是无条件抛异常。要实盘必须先做
   CLOB V2 / 官方 SDK 迁移 + pUSD 抵押品 + 签名路径验证。

3. **实测上**：在我采到的 5 个 common expiry、1,017 个盘口样本里，
   **正 floor 出现 0 次**。最好的一次，成本恰好等于 `1.00000`，
   扣掉吃单费后是 `−0.00007`。市场把这个结构定价到了一个 tick 以内的
   无套利边界上（见 §1.3）。

所以"保证能盈利"我做不到，也没有人能做到。我能做到的是：把"到底有没有钱"
这个问题在 **1 天的本地改动 + 3 天的纸面观测**内答完，而不是再花两周搭
一个注定不会触发的执行探针。

而且按目前的证据，我预期那个答案是"没有"。所以真正的建议是：
**先花 1 天把 Gate 0 修对、让它有资格说话，然后大概率是体面地停掉这条线**，
而不是继续往实盘方向投工程。**我不建议现在实盘。**

## 1. 结构对的完整算术（这是全部争论的核心）

### 1.1 结算不变量

同一个 common close 上，5m 与 15m 共用**同一个** 60 秒 TWAP 终值 `T`，
各自比自己的开盘 TWAP 行权价。记 `b` 为市场隐含的分裂概率：

```
K5 > K15  时： floor 对 = 买 5m Down + 买 15m Up
              b = P(15m Up) − P(5m Up) = P(K15 ≤ T < K5) ≥ 0
K5 < K15  时： floor 对 = 买 5m Up  + 买 15m Down
              b = P(5m Up) − P(15m Up) = P(K5 ≤ T < K15) ≥ 0
```

floor 对在两个"同向"状态各付 1，在分裂状态付 2。所以：

```
最坏收益 = 1
公允价值 = 1 + b
```

**`b ≥ 0` 是结算规则强制的**。这不是经验规律，是恒等式。

### 1.2 三种执行方式的成本（实测：两条腿的买卖价差都是 1 分钱）

设两腿中价为 `m_a + m_b = 1 + b`，taker 费率按官方
`fee = shares × 0.07 × p × (1−p)`（实测 `fd = {r:0.07, e:1, to:true}`）：

| 执行方式 | 每对成本 | 正 floor 的条件 |
|---|---|---|
| 双 taker | `1 + b + 0.01 + fee_a + fee_b` | `b < −(0.01 + fee_a + fee_b)` |
| **一腿挂单 + 一腿 FOK 吃单（= v0.8 选的）** | **`1 + b + fee_hedge`** | **`b < −fee_hedge`** |
| 双腿挂单 | `1 + b − 0.01` | `b < +0.01` |

**关键点**：挂单腿省下的半价差（−0.005）和吃单腿付出的半价差（+0.005）
**精确抵消**。所以 maker+taker 这条路的成本是 `1 + b + fee_hedge`，
在 `b ≥ 0` 时**恒大于 1**。

代入实测费率：

| 价位 p | `fee = 0.07·p(1−p)` | maker+FOK 需要的 b | 双 maker 需要的 b |
|---|---:|---:|---:|
| 0.50 | 0.0175 | < −0.0175 | < +0.01 |
| 0.90 | 0.0063 | < −0.0063 | < +0.01 |
| 0.95 | 0.0033 | < −0.0033 | < +0.01 |
| 0.98 | 0.0014 | < −0.0014 | < +0.01 |
| 0.99 | 0.0007 | < −0.0007 | < +0.01 |

结论：

- v0.8 的 live-eligible 路线（maker + FOK，且要求 `all_in ≤ 0.99`）
  要求 `b ≤ −0.01 − fee`，即**市场把一个恒非负的概率报成了负 1 分钱以上**。
  这不是"结构性约束被执行成本阻挡"，这是"市场报错价"，是一场竞速。
- 双腿挂单只需要 `b < 0.01`。在临近到期、分裂已经基本不可能时，
  `b → 0`，这个条件是**常态可满足**的。

### 1.3 实测：市场把这个结构定价到了**恰好为零**的边界上

这是 2026-08-18 11:15 UTC 到期的真实盘口（`K5 − K15 = +$85.91`，
floor 对 = 买 5m Down + 买 15m Up），最后 60 秒：

```
 ttc  | 5m Down 盘口     | 15m Up 盘口      | 可执行的最便宜组合
   3s | bid 无 / ask 0.001 | bid 0.999 / ask 无 | 0.001 + 0.999 = 1.00000
  25s | bid 无 / ask 0.001 | bid 0.999 / ask 无 | 0.001 + 0.999 = 1.00000
  28s | bid 无 / ask 0.01  | bid 0.999 / ask 无 | 0.01  + 0.999 = 1.00900
  54s | bid 无 / ask 0.01  | bid 0.996 / ask 无 | 0.01  + 0.996 = 1.00600
```

最好的时刻，成本 **恰好等于 1.00000**，floor 恰好等于 0。
再加上吃单腿的费用 `0.07 × 0.001 × 0.999 = 0.00007`，floor 变成 **−0.00007**。

注意此时**两条腿各有一侧盘口是空的**：15m Up 已经没有卖方（结果已定），
5m Down 已经没有买方。唯一可执行的组合就是"吃 5m Down 的 0.001 卖单 +
在 15m Up 的 0.999 挂买单"，而这正好是 1.000。

另一个到期（11:00，分裂状态真的发生了）最后 20 秒：
`5m Down bid 0.99 + 15m Up bid 0.999 = 1.989`，
市场把分裂概率准确地定价成了 0.99。

**市场把这个结构定价到了一个 tick（0.001）以内的无套利边界上。
扣费之后，剩余为负。**

### 2.1 结构 floor 的实测频率

对 5 个 common expiry、1,017 个盘口样本（其中 3 个到期有完整的官方
TWAP 行权价与结算终值、共 241 个 5m 存活窗口样本）：

| 到期 | `K5 − K15` | 结果 | 最便宜可执行组合 | 出现正 floor 的样本 |
|---|---:|---|---:|---:|
| 11:00 | +$12.74 | **分裂发生** | 1.24000 | 0 / 93 |
| 11:15 | +$85.91 | 未分裂 | **1.00000**（含费 1.00007） | 0 / 75 |
| 11:30 | +$44.88 | 未分裂 | 1.00900 | 0 / 73 |

三个到期、三种执行口径（双 taker / maker+FOK / 双 maker），
**正 floor 出现 0 次**。隐含分裂概率 `b` 在 5m 存活窗口内的最小值是
**0.062**，中位数 0.41；`b < 双腿价差之和`（双 maker 正 floor 的条件）
出现 **0 次**。

唯一触到边界的，是 11:15 到期最后 25 秒、结果已经完全确定、
两条腿各有一侧盘口已经清空的窗口——那时成本精确等于 1.00000。
11:30 到期在同样的"已定局"状态下停在 1.00900，因为 5m Down 的卖价
留在了 0.01 而不是 0.001。**边界只在一个 tick 的尺度上被摸到，
从来没有被穿过。**

### 2.2 一个被证伪的假设

我检验了"最后 60 秒散户急于兑现，做市方可以收割"这个假设：
取三个已结算的 5m 市场，统计最后 60 秒吃单方的最终盈亏。

```
到期 1  吃单买"最终输的一方" 3,754 张 @0.016  吃单买"最终赢的一方" 2,093 张 @0.985
到期 2  吃单买"最终输的一方" 5,166 张 @0.115  吃单买"最终赢的一方" 6,210 张 @0.898
到期 3  吃单买"最终输的一方" 3,275 张 @0.014  吃单买"最终赢的一方" 2,051 张 @0.989
```

三个到期合计，站在全部吃单流对面的做市方毛利约 **+$13**，在 $20k+ 的
成交额上等于零。**吃单流本身定价是公允的，方向上没有免费的钱。**
任何 edge 只能来自两条腿之间的相对定价，不能来自单腿的水平。

## 4. 项目当前真实存在的问题

### 4.1 Gate 0 会给出假阴性（P0，必须先修）

**问题 A：结构腿套用了预测腿的价格带过滤器。**

`src/edge_lab/btc_twap_pair_pricing.py:150-161` 的 `select_healthy_pair_books`
要求两条腿的 `best_ask` 都落在 `[0.05, 0.95]`、价差 ≤ 0.03。
Gate 0 通过 `readiness.py:457` 调用它，`build_btc_twap_executable_upper_bound.py:130`
把 v0.7 预注册的 `minimum_market_price=0.05 / maximum_market_price=0.95`
原样传进去。

但 `b → 0`（唯一有正 floor 的状态）必然意味着一条腿在 0.01–0.03、
另一条在 0.97–0.99。**这个过滤器精确地删掉了唯一有机会的区间。**
被过滤的 attempt 在 `readiness.py:464` 直接记为 0。

**问题 B：Gate 0 只在一个固定时刻 tau=240s 取样。**

`build_btc_twap_executable_upper_bound.py:114-124` 强制单一 tau。
tau=240 时 5m 市场刚开 60 秒，`b` 处在最大值附近。
`b` 只在最后 30–90 秒塌缩。**取样点恰好选在最不可能有机会的时刻。**

**问题 C：只算了 taker/taker 一种口径。**
`quote_pair_buy` 只走 ask 侧（`btc_twap_pair_pricing.py:84`），
所以 Gate 0 算的是三种口径里最贵的那一种。

这三个缺陷叠加，Gate 0 几乎必然报"聚合可执行 PnL ≤ 0 → stop route"，
而这个结论**不是市场给的，是过滤器给的**。

```
                  v2_signature_path_verified,
                  trade_terminal_status_reconciled,
                  geoblock_request_ok, geoblock_allows_new_orders
```

- `compatibility.py:30 assert_new_orders_disabled()` 是**无条件抛异常**。
- `ProbeVenue`（`btc_twap_execution_probe.py:892`）是 Protocol，
  **全仓没有任何实现**。
- `ProbePlan` 只在 `tests/test_btc_twap_execution_probe.py:181` 构造过，
  **没有从实时行情生成计划的运行时代码**。
- 本机 `polymarket.com/api/geoblock` **连接超时**（`clob.polymarket.com`、
  `gamma-api`、`data-api`、RTDS WS 都通）。实盘主机必须先证明这一项能通。

好消息：`py-clob-client 0.34.6` 已经支持 `post_order(post_only=True)`、
`OrderType.FOK/FAK`、`cancel_all`，所以适配器的形状是清楚的；
但按仓库自己的合规判定，它不能用于新订单。

### 4.3 数据采集与主机容量（P0，沿用既有结论）

- V0.7 采集失败率 **14/15 = 93.3%**（`DEPLOYMENT_REPORT.md`）。
- `t3.small` CPU credit 曾经跌到 ≈0；磁盘距 15 GiB 软停只剩 **148 MiB**。
- rawcap 实测 **5.3 GB/天**，SPEC 预算 0.3–0.7 GB/天，整盘 50 GB。
- CLOB WS **每约 30 秒断连一次**，每次触发全量 REST 重拍。
  这在纸面轨道只是成本，在实盘是"必须断线即撤单"的硬需求。
- SNS topic **订阅数为 0**，所有告警发进空 topic。
- 清洁合格到期节奏约 **30 分钟 1 个**，100 个样本需要 ≥2 天完美运行。

### 4.4 策略/证据层（沿用既有结论，我复核无异议）

- v0.6 的 +87.52 USDC 是未校准 raw-model 纸面 PnL；
  单个 expiry 占 48.5%，前三个占 93.9%；模型 Brier 两个 horizon 都输给市场。
- 结构线**至今 0 笔经济尝试**，从来没有被经验验证过。
- v0.8 的预测轨道已经 action-disabled，这是对的，保持。

### 4.5 一个次要但值得知道的事实

四个 token 的 book 是**两本**：Up 与 Down 精确镜像
（实测 15up `0.96/0.97` ↔ 15down `0.03/0.04`）。
"四本新鲜 token book"是冗余校验，不是四份独立证据。

## 5. 我建议的顺序

与 GPT 的排序接近，但把"修 Gate 0"提到最前面，把执行形态换掉，
并且明确预期第 1 步就会判负。

| 优先级 | 做什么 | 成本 | 一票否决条件 |
|---|---|---|---|
| 1 | 修 Gate 0 的三个缺陷（§4.1），重跑 41 个已有采集 | 1 天，纯本地 | 修好之后仍然 ≤ 0 → 结构线判负，停 |
| 2 | 用 `QueueScenario` 对**双腿挂单**做 shadow 成交 | 2–3 天 | 中性队列假设下净 PnL ≤ 0 → 停 |
| 3 | 修采集与主机容量（换实例 / 降采集密度 / 补 SNS） | 1 天，运维 | 失败率降不到 5% 以下 → 所有统计无效，停 |
| 4 | 只有 1–3 都过，才做 SDK 迁移 + 适配器 + 最小实盘探针 | 1–2 周 | geoblock 不允许 / pUSD 路径打不通 → 停 |
| 5 | 若 1 或 2 判负：转向有真实补贴的奖励市场，或结束这个方向 | — | — |

第 1 步的价值不在于"可能发现机会"，而在于**用你自己预注册的机器判定
把这条线体面地关掉**，避免半年后又有人问"当初是不是没试全"。
它花 1 天，而第 4 步花 1–2 周且大概率白花。

**不要做的**：继续加 veto、调 tau/lambda、提高 MC 路径数、逆向工程
Chainlink 采样细节、为了凑够 100 笔而放松采集纪律。

## 7. 容量与商业门槛（GPT 问的那个问题，我的答案）

流量是够的，问题是每对的毛利趋近于零。

流量（实测）：

- 每天 96 个 common expiry（15 分钟边界）。
- 每个 expiry 最后 60 秒，5m 腿约 8,800 张极端价位成交；
  15m 腿在 60–300 秒窗口约 4,000–7,600 张。
- 顶档深度 84–420 张，对冲深度不是瓶颈。

毛利（实测）：

- 双 maker 每对的 floor 实测最好值 = **0.000**（扣费后 −0.00007）。
- 理论上界是"两条腿价差之和减去隐含分裂概率"，而在结构安全的极端区，
  15m 腿的价差已经收窄到 **0.001–0.002**，5m 腿仍是 0.01 但其买价被
  中价钉住。**风险消失的地方，价差也消失了。**

所以：

```
即使假设每对能赚 0.002（比实测最好值还乐观），
且每个到期能配对 150 对（很乐观）：
    96 × 150 × $0.002 ≈ $29/天，占用本金约 $500–$2,000
按实测的 0.000，则为 $0/天。
```

**我建议的商业门槛**：连续 14 个 UTC 日，按 expiry 聚合后
**净收益 ≥ $20/天**，占用本金 ≤ $2,000，单 expiry 集中度 ≤ 20%。

**按当前证据，结构线达不到这个门槛，差的不是一点点，是整个量级。**
这个结论不需要 100 个 cluster 才能下——它是恒等式加上一个
"市场把结构定价到一个 tick 以内"的实测事实。
