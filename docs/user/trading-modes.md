# 交易模式：DRY_RUN 与 LIVE

理解每种交易模式的使用时机和方式是安全操作的关键。

## DRY_RUN 模式（模拟交易）

DRY_RUN 模式模拟真实交易但不实际下单。适用于：

- 初始测试和学习
- 策略验证
- 配置调整
- 收集市场数据

### 工作原理

1. 机器人获取真实市场数据（价格、订单簿）
2. 本地模拟挂单和成交
3. 追踪虚拟盈亏和仓位
4. 不涉及真实资金

### 优点

- 零财务风险
- 随时测试
- 自由实验
- 学习系统

### 缺点

- 模拟可能无法反映实际成交率
- 无法测试真实滑点
- 无流动性奖励

### 使用时机

- 首次使用的 1-2 周
- 任何配置更改后
- 测试新市场时

---

## LIVE 模式（实盘交易）

LIVE 模式在 Polymarket 实际下单。适用于：

- 生产交易
- 赚取真实收益
- 获取流动性奖励

### 前置条件

启用 LIVE 模式前需要：

1. **API 凭证**：
   ```bash
   POLY_PRIVATE_KEY=0x...
   POLY_API_KEY=...
   POLY_API_SECRET=...
   POLY_PASSPHRASE=...
   ```

2. **专用交易钱包**
   - 创建新钱包用于交易
   - 切勿使用含主资金的钱包
   - 只转入可承受损失的金额

3. **充足余额**
   - USDC 或 ETH 用于 Gas
   - 足以覆盖目标仓位

### 切换到 LIVE 模式

**方式一：环境变量**
```bash
DRY_RUN=false python run_mm.py
```

**方式二：编辑 .env**
```bash
DRY_RUN=false
```

**然后重启机器人。**

### 优点

- 真实收益
- 流动性奖励
- 真实市场经验

### 缺点

- 真实财务风险
- 需要仔细监控
- 需安全管理 API 密钥

### 使用时机

- 完成 1 周以上 DRY_RUN 测试后
- 理解风险后
- 可承受潜在损失时

---

## 模式切换

### 从 DRY_RUN 切换到 LIVE

1. 完成充分 DRY_RUN 测试（1周以上）
2. 查看安全指南
3. 配置 API 凭证
4. 从小额开始
5. 前 24 小时密切监控

### 从 LIVE 切换到 DRY_RUN

1. 先取消所有挂单
2. 等待pending成交完成
3. 设置 DRY_RUN=true
4. 重启机器人

## 监控您的机器人

### DRY_RUN 监控

- 检查控制台输出
- 审查模拟盈亏
- 验证挂单
- 监控错误

### LIVE 监控（关键）

**需要主动监控** - 每 1-2 小时至少检查一次

- 监控挂单
- 观察仓位和盈亏
- 设置以下告警：
  - 大仓位变化
  - 每日亏损阈值
  - 断连事件

### 终端 UI 仪表盘

使用终端界面进行实时监控：

```bash
python run_tui.py
```

显示内容：
- 当前仓位
- 挂单
- 盈亏
- 市场数据
- 系统状态

## 最佳实践

### 从 DRY_RUN 开始
- 不要跳过此步骤
- 至少测试 1 周
- 在不同市场条件下测试

### 逐步过渡
- 从最小资金开始
- 从小额仓位开始
- 使用低风险配置

### 主动监控（LIVE）
- 初始几小时每 30 分钟检查一次
- 此后每 1-2 小时检查一次
- 市场波动时更频繁
- 准备好应急程序

### 应急程序

出现问题时：

1. 按 Ctrl+C 停止机器人
2. 订单会保持挂起
3. 通过 Polymarket 界面手动取消
4. 审查日志查找问题
