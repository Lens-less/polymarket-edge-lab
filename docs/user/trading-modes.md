# 证据与执行模式

本项目用证据等级描述研究结果，而不是用 `DRY_RUN`/`LIVE` 暗示某个机器人已经可以上线。
本页描述 `v0.2.0` 当前支持的证据与执行模式；`scan/replay/shadow/acceptance/status/desk` 只是固定场景的 developer preview / acceptance surfaces，不是已接真实 snapshot/config 的生产扫描器、生产回放器或完整 UI 启动器。`v0.1.x` 相关措辞仅保留为历史/兼容语义，新单硬门仍然 fail-closed。

| 等级 | 数据与执行 | 能证明什么 |
|---|---|---|
| L0 | 合成数据、单元测试、工程诊断 | 代码路径和不变量 |
| L1 | 公共快照、历史价格、静态 shadow/touch | 候选假设，不证明可成交利润 |
| L2 | 自采前向 L2/WS/RTDS、queue-bounded 模拟 | 仅在预注册门槛全部通过时可称为严格回测证据 |
| L3 | 单独授权的小额真实探针 | 真实成交/scoring/payout 语义 |
| L4 | 真实低风险运行 | 真实表现，仍不保证未来盈利 |

当前发布版只支持 L0–L2 的公开数据研究基础设施。仓库没有 L3/L4 授权，也没有任何命令能把 L0/L1 结果自动升级。

## `DRY_RUN`

`src/config.py` 为保留的通用基础设施提供 `DRY_RUN` 默认值。这不是项目主入口，也不代表模拟成交足以验证策略。合成回测必须明确标记为 L0。

## 认证读取与撤单

仓库保留部分账户读取、成交核对和撤单基础设施，供单独授权的诊断使用。它们需要真实凭证，风险高于公开研究，但仍不能提交新订单。

## 新订单

`src/edge_lab/compatibility.py` 的发布边界无条件拒绝新订单。布尔配置、环境变量、旧研究 gate 或历史部署文件都不能解除它。未来若有新策略，也必须建立新的预注册、授权和独立发布边界；它不属于 `v0.2.0` 的当前支持范围，`v0.1.x` 只保留历史/兼容语义。
