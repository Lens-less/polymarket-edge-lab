# 交易模式：DRY_RUN 与 LIVE

理解每种交易模式的使用时机和方式是安全操作的关键。

> **当前状态（2026-08-20）：LIVE 新订单为 NO-GO。** `DRY_RUN=false`
> 只会进入实盘读取与撤单恢复路径；所有新订单仍被
> `assert_new_orders_disabled()` 硬性拒绝。当前单 outcome 策略也尚未实现
> YES+NO 双 BUY 的库存、盈亏与撤单模型。不要把本页后面的通用配置说明
> 理解成实盘授权。
>
> **另外（2026-08-21）：** 本页下面提到的 `run_mm.py`/`run_tui.py` 是一个与
> 本项目 BTC 5m/15m 结构对策略无关的通用做市机器人的入口，已被删除。
> DRY_RUN/LIVE 的概念本身仍适用于任何未来的执行适配器，但这两个具体命令
> 已不存在，见 `../../CLAUDE.md`。

## DRY_RUN 模式（模拟交易）

DRY_RUN 模式模拟真实交易但不实际下单。适用于：

- 初始测试和学习
- 策略验证
- 配置调整
- 收集市场数据

### 工作原理

1. 机器人获取真实市场数据（价格、订单簿）
2. 本地模拟挂单和成交
3. 追踪虚拟盈亏和仓位
4. 不涉及真实资金

### 优点

- 零财务风险
- 随时测试
- 自由实验
- 学习系统

### 缺点

- 模拟可能无法反映实际成交率
- 无法测试真实滑点
- 无流动性奖励

### 使用时机

- 首次使用的 1-2 周
- 任何配置更改后
- 测试新市场时

## LIVE 模式（当前仅限读取与恢复）

当前 checkout 中的 LIVE 模式用于验证认证读取、同步账户状态和撤销遗留订单，
不能提交新订单。

### 前置条件

启用 LIVE 模式前需要：

1. **API 凭证**：
   ```bash
   POLY_PRIVATE_KEY=0x...
   POLY_API_KEY=...
   POLY_API_SECRET=...
   POLY_PASSPHRASE=...
   ```

2. **专用交易钱包**
   - 创建新钱包用于交易
   - 切勿使用含主资金的钱包
   - 只转入可承受损失的金额

3. **充足余额**
   - USDC 或 ETH 用于 Gas
   - 足以覆盖目标仓位

### 设置 LIVE 读取模式

**方式一：环境变量**
```bash
DRY_RUN=false python run_mm.py
```

**方式二：编辑 .env**
```bash
DRY_RUN=false
```

**然后重启机器人。** 启动后新订单仍会被硬门拒绝；此设置不会解除发布门。

### 将来解除硬门前的库存前置条件

即使将来完成独立授权并解除新订单硬门，当前单 outcome 做市路径也不能从
零库存自举：

- `sellable = min(outcome token balance, allowance)` 必须至少达到
  `MIN_ORDER_SIZE`，否则 ask 被禁用；为避免退化为单边累积多头，bid 也会被禁用。
- 钱包总余额与所有未成交买卖单的最坏情形暴露必须不超过动态有效风控上限
  （通常受 `RISK_MAX_POSITION` 约束）。
- 要保持双边报价，钱包暴露还必须低于 `MAX_LONG` 库存区间；该区间由
  `MM_POSITION_LIMIT` 的库存百分比控制。
- 钱包余额用于资金与硬风控；VWAP 和未实现盈亏只归因于本次进程启动后的成交。
  运行期间如发生手工转账、split、merge、redeem 或其他进程交易，应立即停机、
  撤单并重新核对，不得把外部余额变化当作本策略盈亏。

这些条件只是必要条件，不是实盘许可。完整 YES+NO 双 BUY 模型、最小认证成交
验证和发布审计仍是解除硬门的前置工作。

### 当前可验证内容

- 认证账户余额与订单读取
- 增量成交同步和 maker/taker 归一化
- 撤单、断连恢复和关停验证

### 风险与限制

- 需要管理真实 API 凭证和专用钱包
- 不能验证真实新订单、排队位置或双边成交
- 不构成收益、流动性奖励或实盘就绪证明

### 使用时机

- 仅限单独授权的认证读取、撤单或最小成交取证工作
- 不用于常规策略运行

## 模式切换

### 从 DRY_RUN 切换到认证读取/恢复

1. 完成充分 DRY_RUN 测试（1周以上）
2. 查看安全指南
3. 使用专用钱包并配置最小权限 API 凭证
4. 明确本次只读或撤单授权范围
5. 确认新订单硬门仍然开启

### 从 LIVE 切换到 DRY_RUN

1. 先取消所有挂单
2. 等待pending成交完成
3. 设置 DRY_RUN=true
4. 重启机器人

## 监控您的机器人

### DRY_RUN 监控

- 检查控制台输出
- 审查模拟盈亏
- 验证挂单
- 监控错误

### LIVE 监控（关键）

**需要主动监控** - 每 1-2 小时至少检查一次

- 监控挂单
- 观察仓位和盈亏
- 设置以下告警：
  - 大仓位变化
  - 每日亏损阈值
  - 断连事件

### 终端 UI 仪表盘

使用终端界面进行实时监控：

```bash
python run_tui.py
```

显示内容：
- 当前仓位
- 挂单
- 盈亏
- 市场数据
- 系统状态

## 最佳实践

### 从 DRY_RUN 开始
- 不要跳过此步骤
- 至少测试 1 周
- 在不同市场条件下测试

### 逐步过渡
- 从最小资金开始
- 从小额仓位开始
- 使用低风险配置

### 主动监控（LIVE）
- 初始几小时每 30 分钟检查一次
- 此后每 1-2 小时检查一次
- 市场波动时更频繁
- 准备好应急程序

### 应急程序

出现问题时：

1. 按 Ctrl+C 停止机器人
2. 等待自动撤单验证；若日志显示撤单超时，后台线程可能仍在继续
3. 立即通过 Polymarket 界面核对并手动取消所有剩余订单
4. 审查日志查找问题
