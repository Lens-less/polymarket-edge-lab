# 安全指南

**⚠️ 警告：交易预测市场存在重大亏损风险。**

本软件仅供教育和研究目的。在充分了解风险之前，请勿投入真实资金。

> **当前版本不能实盘开新仓。** 新订单发布门仍被硬编码关闭；`DRY_RUN=false`
> 不会解除该门。当前策略也没有完成 YES+NO 双 BUY 的双边库存模型。

---

## 关键安全规则

### 1. 切勿使用个人钱包密钥

**这是最重要的规则。**

- 创建专用交易钱包
- 切勿使用含个人资金的主钱包
- 只转入可承受损失的金额
- 保持交易钱包分离

```bash
# 错误 - 切勿这样做
POLY_PRIVATE_KEY=0x您的主钱包私钥

# 正确 - 使用专用交易钱包
POLY_PRIVATE_KEY=0x专用交易钱包私钥
```

### 2. 从小额开始

- 从最小仓位开始
- 证明系统稳定后逐步增加
- 初始使用保守配置

**建议初始值：**
```bash
MM_SIZE=5
RISK_MAX_POSITION=20
RISK_MAX_DAILY_LOSS=10
```

### 3. 初始阶段主动监控

开始实盘交易时：

- 前几小时每 30 分钟检查一次
- 此后每 1-2 小时检查一次
- 市场波动时更频繁

### 4. 先使用 DRY_RUN

- 在 DRY_RUN 模式充分测试
- 等待至少 1 周后再实盘
- 在不同市场条件下验证

## 自动安全功能

机器人内置多项自动保护：

### 熔断机制（Kill Switch）

满足以下条件时自动停止交易：
- 每日亏损超过 `RISK_MAX_DAILY_LOSS`
- 连续错误过多
- 仓位超出限制

### 余额监控

- 下单前检查余额
- 余额意外下降 20% 以上时告警
- 帮助检测未经授权的访问或错误

### 断连自动取消（Cancel-on-Disconnect）

- WebSocket 断连时自动取消所有订单
- 防止波动市场中形成僵尸订单
- 需要手动重启恢复
- 关停等待有时间上限；如日志提示撤单仍在后台运行，必须到 Polymarket 界面
  手工确认账户内没有活单

### 钱包余额与策略盈亏分离

- 钱包 outcome token 总余额用于可卖量、仓位上限和最坏情形暴露检查
- VWAP 与未实现盈亏只使用本次进程启动后归因到该策略的成交
- 启动前持仓没有可验证成本时，不会伪造历史 VWAP
- 运行中如发生外部转账、split、merge、redeem 或手工交易，立即停机并重新核对

### 僵尸订单清理

- 移除超过 5 分钟的订单
- 防止僵尸订单
- 帮助保持仓位准确

## 应急程序

### 机器人无响应

1. 按 `Ctrl+C` 停止机器人
2. 在 polymarket.com 手动取消订单
3. 审查日志查找错误
4. 修复问题后重启

### 意外亏损

1. 立即停止机器人
2. 取消所有订单
3. 检查 `RISK_MAX_DAILY_LOSS` - 机器人应该已暂停
4. 审查近期活动
5. 调整配置后再重启

### WebSocket 断连

- 机器人会自动取消订单
- 等待重连（通常 10-30 秒）
- 如持续断连，手动重启

### 疑似未经授权访问

1. 立即撤销 API 密钥
2. 从交易钱包转移资金
3. 检查交易记录
4. 如需要创建新 API 密钥

## 账户成交语义取证脚本

`scripts/probe_account_trade_semantics.py` 是一个只读脚本，用于捕获真实的
`ClobTrade`/`MakerOrder` 载荷，核实 `src/orders.py` 里关于成交方向、
maker 身份识别、手续费公式的假设是否成立。它不下单、不撤单、不修改任何
订单——但读取的是真实账户的成交与挂单记录，运行前请遵守：

- **使用隔离钱包**，不要用持有个人资金的主钱包；脚本落盘的记录里
  maker/owner 地址只做部分脱敏（保留前 6 位、后 4 位），不是完全匿名。
- **只转入最小可交易额度**。
- 该脚本本身不下单；如果想捕获一笔新的 maker 成交，需要你自己在另一个
  会话里挂一个小额被动单，等它成交或部分成交后运行本脚本，然后**立即
  撤销剩余挂单**，不要让订单空转。
- 未配置凭证时会给出明确的前置条件说明并以退出码 1 结束，不会抛出异常。

用法：

```bash
python scripts/probe_account_trade_semantics.py TOKEN_ID [--out DIR] [--limit N]
```

输出：脱敏后的原始成交 JSON 与一份 Markdown 报告，写入 `--out`（默认
`logs/probes/`）。报告尝试回答四个问题（maker 时 `ClobTrade.side` 是否为
taker 方向、`maker_address`/`owner` 能否稳定识别自己的 maker 腿、
`fee_rate_bps` 对应哪种手续费公式、一笔 taker 成交是否会产生多条本账户
maker 腿），并给出钱包余额与推导仓位变化的一致性对照。

## 出问题时怎么办

1. **保持冷静** - 不要仓促做决定
2. **停止机器人** - 首先取消所有订单
3. **评估情况** - 检查仓位、盈亏、日志
4. **限制损失** - 如需要平仓
5. **学习调整** - 审查问题所在
6. **从小开始** - 不要报复性交易
