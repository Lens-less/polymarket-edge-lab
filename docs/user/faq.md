# 常见问题

## 这个仓库做什么？

它收集和回放 Polymarket 公开数据，审计交易假设的定价、成交与证据质量。它不是可直接运行的做市机器人，也不是 Polymarket 官方项目。

## 开箱验收需要账户或网络吗？

不需要。按[快速开始](getting-started.md)运行 `--validate-only` 即可完成离线验收。

## 现在能实盘吗？

不能。仓库中没有已验证盈利策略，新订单边界无条件关闭；`DRY_RUN=false` 不会改变这一点。

## 为什么还保留交易、风控和部署代码？

这些代码用于历史复现、回归测试或未来研究的通用基础设施。`deploy/` 是历史资产，不是当前部署说明。

## `audit` 为什么可能失败？

它会检查 SDK 安装状态并访问 Polymarket 的公开 geoblock 端点。网络不可达、响应异常或地域限制都会产生 fail-closed 结果；这不影响离线研究命令。

## 为什么 mock backtest 是亏损的？

该路径刻意用合成数据强制成交，只用于验证账本和报告，不是策略示例，也不应调参成“盈利截图”。

## 大型数据在哪里？

本地采集默认写入被 Git 忽略的 `data/`。仓库只保留版本化报告、manifest 和部分紧凑证据。详见 [`DATASETS.md`](../../DATASETS.md)。

## 如何贡献？

先读[贡献指南](../../CONTRIBUTING.md)，在改代码前运行相关测试。Bug 报告应包含最小复现、环境和脱敏后的错误信息。

## 如何报告安全问题？

按 [`SECURITY.md`](../../SECURITY.md) 使用 GitHub 私密漏洞报告。不要把真实凭证或可利用细节放进公开 Issue。
